## 4. Latency

### Key-to-action path today (2.5's tester session, `p2-2.5-latency-trim/bench/H1.md`)

- **Delivery** of the hook call to the main thread: R7 is a 10.1 us round trip. R8 one-way is 6.5-7.7 us p50, with a p99
  of 99-290 us under load.
- **Callback:** R12 0.2 us; R4 0.2 us p50, 0.8 us p99; R9 0.2 us; R10 0.4 us; R11 0.8 us; R12m 0.8 us; R12m2 1.4 us.
- **Action:** unmeasured. Delivery dominates. The budget's "100 us" is two orders of magnitude above the callback's bench
  p99, but within the field maximum (F-16).

### Lane A

- **Bench code only:** zero change to the key path.
- **Optional counter:** one `Duration` compare per callback (about 1 ns), plus one atomic RMW only for a callback of
  100 us or more. No allocation, lock, `log::`, Win32 call, wake-up or timer change.

### Lane B (or 3.2), the after-match rule

- **Removed:**
  - On every unrelated non-repeat key-down, for each `sequence`/`chord` binding with a title condition: one
    `GetWindowTextW` (OnceCell, once per event; R10-R9 is about 0.2 us), its `String`, and two `to_lowercase` `String`s
    (`condition.rs:63`).
  - For `AppEquals`: a cache read only (`foreground.rs:150-152`).
- **Added:** at a key-down of a sequence binding, a classification of a few compares before the feed. Sequences with no
  pending entry and no step-0 key pressed skip `when:`.
- **Unchanged:** no change for configs without sequence/chord conditions (the template and the owner's config: R1-R18
  stay put). No lock, wake-up or timer change.

### F3 default (no code)

- None. The live `GetForegroundWindow` stays where it is.
- If TF-5 flips, one call (R17f) leaves the hook path per fired `Sequence`. If row 80 is fixed later, one call per
  key-down that evaluates `AppEquals` comes onto it (OQ-4).

### Technical forks (my recommendation; the architect or orchestrator decides)
